## MAJOR — 7

- **Cyclic `@import` could recurse without bound**, imported rules were attributed to the
  importing sheet, import media was dropped, and the callback never actually supplied the
  `sheetIndex`/`ruleIndex` that `MatchedRules` requires. Rewritten with a
  `WeakSet<CSSStyleSheet>`, per-sheet provenance, import media folded into the condition
  stack, and a `RuleSite` passed to every visit — which is what makes Task 6's source-order
  tie-break implementable rather than aspirational.
- **`definedIn` was unimplementable for inline definitions.** `style="--brand:…"` never
  enters `document.styleSheets`, so Task 6 could claim a winner it had no data for. Now
  walks inline styles up the chain (`definedIn: '[inline]'`, beating stylesheet rules at
  equal depth), and emits a new `indeterminate-definition` omission when the site cannot be
  established at all.
- **Standard mode overclaimed what Deep disclaims.** "The winning definition" implied a
  cascade resolution spec §6.2 explicitly refuses for Deep. Renamed to the **observed**
  definition throughout.
- **Frame delivery was still unguaranteed.** A 30fps paint loop is better than two `rAF`s
  but proves nothing, and the clamp and hint tests still used one-shot streams. Production
  now awaits `loadedmetadata` plus `requestVideoFrameCallback` with a bounded 3s fallback,
  returning `null` with `no frame delivered` rather than a blank canvas. All crop tests
  share one injected `__mkStream` helper.
- **Two test-harness leaks.** The paint loop stopped only on success, leaving a
  self-scheduling `rAF` alive after a rejection; and the cleanup test patched
  `HTMLCanvasElement.prototype.getContext` globally, restoring it only after the awaited
  call. Both fixed with `try/finally`, and the prototype patch replaced by an injected
  `canvasFactory` seam — a failure seam belongs in the API, not in a global prototype.
- **The screenshot rule contradicted itself in three places at once** — Global Constraints
  and the manual checklist said "disabled on Firefox/Safari" while Task 9 and the spec said
  it degrades. Resolved to degradation everywhere.
- **`getSupportedConstraints()` was worse than unreliable.** It enumerates *track*
  constraints and the Screen Capture spec's list does not include `preferCurrentTab`, so it
  reports the hint absent even on Chromium. Dropped entirely: `preferCurrentTab: true` is
  now passed unconditionally, since an engine that does not implement a dictionary member
  ignores it. One fact, one function, no branch to get wrong.
- **Spec §6.3 still promised "typography with the fallback flag"** after the heuristic was
  cut — a field a Markdown implementer would have had to invent. Replaced with the actual
  `webfontStatus` contract.

## Retrospective across all three rounds

56 findings, 55 accepted, 1 rejected on the facts. The rejection is logged in round 1 with
reasoning; codex agreed in round 2 that the assertion would have passed as written.

Three of the four round-3 CRITICALs were **defects in my own round-2 fixes**, not in the
original plan. That is the argument for the loop: the first fix to a privacy hole was
incomplete, and the fix to the server race introduced a new failure that would have broken
every CI run. Neither would have surfaced without a reviewer re-reading the repairs.

The two genuine privacy holes — container text leaking descendant user data, and URL
schemes laundering a payload through an allowlisted attribute — were both found by review,
and neither would have been caught by the plan's own redaction gate as originally written,
because the fixtures were too simple to trigger them. The fixture set is now built to
trigger exactly those cases.
